# Evidence ledger protocol (frozen before extraction)

Status: DRAFT until approved. Once approved, do not edit this file after any evaluate.py run.

## Unit of evidence
One row in `evidence_ledger.csv` = one condition x feature x study, with k (patients with the feature) and n (full-cohort denominator), re-extracted from the original paper. Record the table/page the numbers came from.

## Inclusion for pooling (poolable = Y)
- Primary study with numeric k and n for the full cohort of confirmed cases.
- Excluded from the primary pool (poolable = N, still recorded): meta-analyses and reviews (already pooled; used as comparators), textbook/guideline summaries (sanity checks), subset-only cohorts (severe-only, CNS-only, DHF-only), and anything where the denominator is not the whole confirmed cohort.
- Age: all ages pooled; `age_group` = adult / paediatric / mixed. Sensitivity pass re-pools with paediatric-only rows excluded (`--exclude-paediatric`) and reports which cells move.
- Country: India preferred. If a cell has >=3 India studies, pool India only. Otherwise pool India plus others and flag the cell `non_india_mix`.

## Pooling
- >=3 studies: DerSimonian-Laird random effects on logit scale, 0.5 continuity correction for k=0 or k=n; report value, 95% CI, I2.
- 2 studies: n-weighted raw proportion. 1 study: raw k/n.
- Table value = pooled value. No hand-chosen "midpoints".

## Uncertainty
- Single/two-study cells: Beta(k+1, n-k+1). Pooled cells: normal on logit scale with SE including tau^2. `--resample N` writes draws.
- Rerun evaluate.py per resampled table to report top-1/top-3 as ranges. Also leave-one-source-out per condition.

## Unsourced cells  [OPEN: needs a decision]
A flat 0.5 placeholder is NOT safe: for eschar, only scrub typhus has a source (0.285), so a 0.5 placeholder on other conditions would make a positive eschar favour them over scrub typhus. Options:
 A. Placeholder = mean of the sourced cells for that feature (likelihood ratio ~1, feature uninformative for unsourced conditions). Wide Beta in resampling.
 B. Add a third tier of evidence: guideline-listed present/absent from the ICMR/MoHFW corpus mapped to coarse values, flagged `guideline_tier`.
 Either way, keep legacy values in a separate column, never silently reuse them.
Also check diagnose.py floors probabilities: exact 0.0 eliminates a condition on one positive feature.

## Run discipline
Fix this file, build the table from the ledger, run evaluate.py once, report the result whether it rises or falls. No tuning afterwards.

## Feature mapping (added after the first extraction; OPEN items marked)
Papers report "any rash", "any lymphadenopathy", "myalgia", and individual GI symptoms; several model features are narrower or composite. Every row carries `mapping`:
- exact: paper's definition matches the feature. Pools.
- proxy: paper reports a broader or looser version (skin rash for rash_maculopapular, any lymphadenopathy for lymphadenopathy_reg, any myalgia for myalgia_severe). Pools, but reported separately in the sensitivity pass.
- component: paper reports one part of a composite feature (vomiting or abdominal pain for gi_symptoms). Never pooled into the composite.
OPEN: gi_symptoms is "diarrhoea, vomiting or abdominal pain". No paper so far reports the union. Options: (a) split into component features in the model, (b) use the largest reported component as a lower bound and flag it, (c) keep the cell unsourced. The old table value of 0.45 for scrub typhus mixed two different components, which is not defensible.

## Derived counts
If a paper gives only a percentage, k may be back-calculated but is flagged `DERIVED` in notes and is never pooled unless the paper also states the count.

## Meta-analysis override (APPROVED)
Default: meta-analyses are comparators and are not pooled with their own component studies. Exception, applied only when all four hold, and decided before any evaluate.py run:
1. the meta-analysis is India-specific and reports a random-effects pooled proportion with a 95% CI;
2. it covers all confirmed cases of the condition (not a subset such as CNS-only or severe-only);
3. its total n is at least 10x the total n of the poolable primary rows for that cell;
4. the ledger row is marked use_as_cell_value = Y.
The meta-analysis value then becomes the cell value, resampled as a normal on the logit scale using its CI. The primary pool is still reported next to it (primary_pool) so the two can be compared.
First use: scrub typhus eschar, Gupta 2024 (28.5%, CI 24.1-32.9%, 34,002 cases) against the primary pool of 4 studies (n=1,011). Caveat: the age mix of its included articles is not stated in the abstract.

## GI symptoms: RESOLVED (replaces the OPEN item above)
Decision: keep gi_symptoms as ONE composite feature. Reasons: the CLI asks it as one question; the vignettes carry a single GI flag, so a split could not be evaluated and no gain could be shown; and extra correlated component features would add naive-Bayes double counting.
Cell value: component rows are marked poolable = C and pooled per component; the composite cell takes the LARGEST pooled component as a flagged lower bound for "any GI symptom" (basis = lower_bound:<component>). The union is not measured by any source, so pooled_long.csv also reports gi_upper_sum (sum of components, capped at 1) and gi_indep (1 - product of (1 - component)), which bracket it.
Sensitivity run (mandatory, one extra evaluate.py run, reported either way): replace every gi_symptoms cell with gi_indep and report the change in top-1 / top-3. If the metrics barely move, the unmeasurable union is harmless for the results.
Possible improvement: look for papers that report "any gastrointestinal symptom" directly, which would give a real union for that cell.
